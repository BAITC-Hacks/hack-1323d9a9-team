# Почасовой прогноз мощности двух ветротурбин

Система получает архивный прогноз ECMWF по координатам станций, проверяет
доступность погодного выпуска на момент прогноза, строит признаки, запускает
scikit-learn модель и сохраняет результат с журналом происхождения данных.
Горизонт — 24–48 часов, мощность нормирована и ограничена `[0, 1]`.

Исходные SCADA: март 2023 — январь 2026. Время SCADA — местное
`Asia/Almaty` (подтверждено владельцем данных); API и журнал используют UTC.
Тестовый период — февраль 2026 по местному календарю станции.

## Установка и запуск

Проверенная среда — Python 3.14. Версии библиотек закреплены, поскольку
joblib-артефакты scikit-learn зависят от версии библиотеки.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Документация API: `http://127.0.0.1:8000/docs`. Работа не требует ключа OpenAI
или другого LLM: агент реализован как проверяемый автомат состояний, который
сам получает данные, готовит признаки, проверяет результат и версионирует его.
`frontend/` пока не содержит интерфейса; для демонстрации используется Swagger.

```powershell
$requestBody = '{"issue_time":"2026-01-31T18:00:00Z","horizon_hours":48}'
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/forecast/run -ContentType application/json -Body $requestBody
Invoke-RestMethod http://127.0.0.1:8000/api/forecast/latest
Invoke-RestMethod http://127.0.0.1:8000/api/metrics
```

`/health` проверяет доступность API. Для проверки готовности всего конвейера
нужен `/api/forecast/run`: сбои источника погоды/модели возвращаются явно.
Используйте один worker API: блокировка распределения номеров версий сейчас
действует внутри одного процесса.

## Воспроизведение данных и моделей

```powershell
python -m ai.models.scada_preprocessing
python -m ai.models.baseline_forecasting
python -m ai.services.archive_download --start 2025-11-29T18:00:00Z --end 2026-01-30T18:00:00Z --step-hours 6 --workers 1
python -m ai.models.train --scada-timezone Asia/Almaty
```

Raw CSV не изменяются; часы с менее чем тремя измерениями отбрасываются,
разрывы не заполняются. Training заканчивается 31.12.2025, validation —
январь 2026. Baseline использует измеренную SCADA-погоду и оценивает условную
зависимость мощности от погоды. Его метрики не являются точностью реального
прогноза с неизвестной будущей погодой.

Production-кандидаты ExtraTrees и HistGradientBoosting используют исключительно
архивные погодные прогнозы и те же фактические значения мощности. Данные с
примерным горизонтом 24 и 48 часов объединяются; алгоритмы сравниваются на
одинаковых строках января. Автоматический случайный holdout отключён.
Для демонстрационного обучения загружается период около декабря 2025 — января
2026; точные фактические границы записаны в metrics. Архив можно расширить
параметрами download-команды.

Выбор production-модели использует только январские целевые значения, час
которых завершился к `2026-01-30T19:00Z` (00:00 местного времени 31 января).
Оставшаяся часть января участвует в итоговых метриках, но не в выборе: это
позволяет честно выпустить 31 января прогноз на весь день 1 февраля с
минимальным горизонтом 24 часа. Предполагается,
что почасовая мощность доступна сразу после окончания часа; дополнительная
задержка SCADA не предоставлена.

Результаты: `ai/models/artifacts/metrics.json` — даты, признаки, выбор,
метрики всех кандидатов, параметры, хеши данных и сравнение на одинаковой выборке.
`turbine_X_archived_training_rows.csv` сохраняет каждую строку с issue/run/valid
time и фазой её использования. `turbine_1.joblib`/`turbine_2.joblib` сохраняются
как baseline; production-модели имеют суффикс `_archived.joblib`. Загрузчик
выбирает артефакт по metrics. При недостаточном архиве fallback явно маркируется
в API-предупреждениях. Baseline выбран по всему январю и не доступен для первого
выпуска в 00:00 31 января; такой запуск с fallback будет отклонён.

## Официальная историческая симуляция февраля

```powershell
python -m ai.services.archive_download --start 2026-01-30T19:00:00Z --end 2026-02-27T19:00:00Z --step-hours 24 --workers 1
python -m ai.services.rolling_backtest --cache-only
```

29 ежедневных выпусков в 00:00 местного времени с 31 января по 28 февраля,
каждый на следующие 48 часов. Неизменяемые JSON каждого выпуска лежат в
`data/forecasts/rolling/`; полный журнал `rolling_forecasts.csv` содержит 2784
строки с перекрытиями. В `february_evaluation.csv` по правилу «самый свежий
выпуск с lead не меньше 24 часов» остаются 1344 строки — по одной на каждый
февральский час и турбину. `rolling_report.json` проверяет все 29 выпусков,
времена и покрытие; при ошибке возвращается ненулевой код. Политики и поля
описаны в [docs/backtesting.md](docs/backtesting.md). Старый
`ai.services.replay` (выпуск в 23:00, 28 запусков) сохранён как дополнительный
технический прогон, не как официальная оценочная таблица.

Фактическая мощность за февраль не предоставлена: февральские MAE/RMSE/R²
не вычисляются и не заявляются. Януарские метрики — validation, не test.

## Источник погоды и ограничения

Используется [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api)
с конкретным `run`, моделью `ecmwf_ifs`, скоростью в м/с и UTC.
[Previous Runs](https://open-meteo.com/en/docs/previous-runs-api) предоставляет
серии с фиксированным смещением 24/48 часов, но не идентифицирует единый полный
запуск так же явно. Поэтому код использует Single Runs.

Инвариант: `weather_run_time + 6h <= issue_time < valid_time`.
Шесть часов — консервативная политика публикации, а не фактическая историческая
отметка получения каждого выпуска. В cache сохраняются исходный ответ,
параметры запроса и SHA-256; сеть не подменяется наблюдениями или реанализом.
Ранние hindcasts IFS 49r1 исключены: согласно
[ECMWF](https://www.ecmwf.int/en/forecasts/documentation-and-support/changes-ecmwf-model)
этот цикл стал операционным 12.11.2024.

Признаки: wind_speed_80m/100m/120m, wind_direction_100m, temperature_2m,
surface_pressure, циклические час и день года. Некоторые высоты ветра
предоставляются API как производные поля, а не независимые измерения.
Cache не коммитится; первоначальная загрузка требует сети и зависит от лимитов
Open-Meteo. Повторите download-команду для дозагрузки после HTTP 429.

Программные тесты включают контролируемые fixtures. Их результаты проверяют
конвейер, но не заменяют проверку прогноза на настоящих архивных данных.
Подробности аудита — [docs/project-audit.md](docs/project-audit.md).
