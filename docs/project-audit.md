## Исправленные дефекты

1. Разбор SCADA терял все часы 00–09: `fromisoformat` не понимал строки с
   однозначным часом. Теперь январь содержит 744 строки на каждую турбину
   вместо 434. Raw CSV не изменялись. Обработанные данные и модели пересобраны.
2. Локальное время ошибочно считалось UTC. Владелец подтвердил местное время;
   используется `Asia/Almaty`, включая смену UTC-смещения в исторических данных.
3. HistGradientBoosting мог делать случайный holdout для early stopping.
   Он отключён; только хронологическая январская валидация.
4. Trainer мог перезаписать fallback, неверно называл Single Runs как Previous
   Runs и сравнивал lead-группы на разных targets. Архивные артефакты разделены,
   источник исправлен, 24/48 группы объединены для одинакового сравнения.
5. Пустой cache раньше принимался за недоступность архива без попытки загрузки.
   Реально загружены 498 запросов для обучения/валидации, с повтором 10 запросов
   после HTTP 429. Есть команда дозагрузки и режим без сети.
6. Клиент проверяет источник, координаты/запрос, checksum, единицы, временную
   сетку и момент публикации. Ранние IFS49r1 hindcasts не считаются доступными
   историческими прогнозами. Пропуски дальнего хвоста не интерполируются.
7. Агент раньше прогнозировал все 240 часов ответа, в том числе прошлые; API
   фильтровал их, а latest возвращал другой результат. Теперь сохраняется ровно
   нужный будущий горизонт, наличие всех часов проверяется до предсказания.
8. Загрузчик игнорировал выбранное имя модели и использовал имя алгоритма
   вместо версии содержимого. Теперь выбирает записанный артефакт и проверяет
   признаки, SHA и время доступности модели; fallback явно предупреждает
   о переносе с измеренной погоды на прогнозную.
9. Выбор по всем targets января конфликтовал с первым выпуском на местное
   1 февраля. Selection cutoff production — 31 января 23:00 местного времени.
   Последний январский час используется только для итоговых метрик.
10. Нефинитные значения, конфликтующие дубли и неполные горизонты отклоняются;
    запись результата атомарная. Появился контролируемый replay всего февраля.
11. API-тестам не хватало `httpx2`, требуемого установленной Starlette. Зависимости
    и IANA tzdata для Windows добавлены; версии закреплены.

## Метрики на январе 2026

Мощность нормирована. Baseline ниже использует измеренную погоду и является
оптимистичным диагностическим сравнением. Archived модель использует только
сохранённые прогнозы, имевшие допустимый run на соответствующий issue.

| Турбина | Модель / входы | MAE | RMSE | R² |
|---|---|---:|---:|---:|
| 1 | ExtraTrees, измеренная SCADA | 0.022363 | 0.047082 | 0.980516 |
| 1 | ExtraTrees, архивные прогнозы | 0.237376 | 0.284726 | 0.287449 |
| 1 | HistGradientBoosting, архивные прогнозы — выбран | 0.198192 | 0.274842 | 0.336063 |
| 2 | ExtraTrees, измеренная SCADA | 0.024484 | 0.060487 | 0.967901 |
| 2 | ExtraTrees, архивные прогнозы | 0.244247 | 0.295006 | 0.236471 |
| 2 | HistGradientBoosting, архивные прогнозы — выбран | 0.221346 | 0.287141 | 0.276639 |

Валидация: 744 уникальных target-часа, два горизонта, 1488 строк/турбину.
Фактическое архивное обучение: 30.11.2025 20:00 — 31.12.2025 23:00 местного
времени; 748/744 уникальных target-часа для турбин 1/2. Не все начальные часы
имеют оба lead; точные строки и фазы сохранены в `*_training_rows.csv`.
`metrics.json` содержит также selection-only MAE, отдельные lead-метрики,
параметры алгоритмов, версии библиотек, fingerprints входов и audit CSV.

Признаки 1–20-часового горизонта ещё не оценены отдельно: модель обучалась
около 24/48 часов (±3 часа). Применение ко всем 1–48 часам работает, но его
точность не равна приведённым lead-метрикам.

## Проверки и воспроизведение

Выполнены:

```powershell
python -m ai.models.scada_preprocessing
python -m ai.models.baseline_forecasting
python -m ai.services.archive_download --start 2025-11-29T18:00:00Z --end 2026-01-30T18:00:00Z --step-hours 6 --workers 1
python -m ai.models.train --scada-timezone Asia/Almaty
python -m unittest discover -s tests -v
python -m ai.services.replay
python -m ai.services.replay --cache-only
python -m pip check
```

Полный набор: 82 теста, без skipped. В тестах погодные fixtures проверяют
ошибки и пограничные случаи; реальный replay выполнен отдельно через архивный
API с настоящими артефактами. Все 28 выпусков завершились, полный февраль
покрыт на обеих турбинах; сохранено 2640 forecast-строк с перекрывающимися
горизонтами. Точные доказательства — `data/forecasts/february/replay_report.json`,
`february_forecasts.csv` и отдельные JSON каждого выпуска.

Повторный февральский replay без сети также завершён: 28/28, 672 часа/турбину.
Локальный Uvicorn проверен настоящими HTTP-запросами: `/health` — `ok`,
`/api/forecast/run` — `COMPLETE`, 96 точек для 48 часов и двух турбин;
`/latest` вернул тот же input hash и 96 точек. Сервер после проверки остановлен.

В ограниченной Windows-песочнице стандартные temporary directories недоступны.
Поэтому тесты и обучение запускались с разрешением вне неё. Это ограничение
данной среды запуска, а не замена неудачных проверок успешными fixtures.

Источник и предположения публикации приведены в [README](../README.md).
Невозможно подтвердить идеальную точность или полную operational availability
каждого исторического запуска без дополнительных данных провайдера.
